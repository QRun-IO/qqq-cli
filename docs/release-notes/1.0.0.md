# qqq 1.0.0

**qqq 1.0**: the command-line client and the full-screen terminal UI for
[QQQ](https://github.com/QRun-IO/qqq) applications, in **one binary per platform**. Everything comes from
the server's metadata through the QQQ UI API, so the same binary works with any QQQ application.

Works with servers on UI API 1.6.0 up to 2.0 (QQQ 4.1.0-RC.15 or later). `qqq --version` shows the range.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/QRun-IO/qqq-cli/main/scripts/install.sh | sh -s -- --version 1.0.0
```

Or download the binary for your platform below and check it against `SHA256SUMS`:

| Platform | File |
|---|---|
| macOS, Apple silicon | `qqq-darwin-arm64` |
| macOS, Intel | `qqq-darwin-x64` |
| Linux x64 / arm64 (glibc) | `qqq-linux-x64`, `qqq-linux-arm64` |
| Linux x64 / arm64 (musl, Alpine: `apk add libstdc++ libgcc`) | `qqq-linux-x64-musl`, `qqq-linux-arm64-musl` |
| Windows x64 | `qqq-windows-x64.exe` |

The npm package (`npm install -g @qrun-io/qqq-cli` from GitHub Packages, Node 20+) has the CLI
without the terminal UI.

**macOS:** these binaries are not notarized yet. A binary downloaded with a browser is stopped by
Gatekeeper; clear the flag once with `xattr -d com.apple.quarantine ./qqq-darwin-arm64`. The installer
above does not set it. **Windows:** the `.exe` is not signed yet, so SmartScreen may warn on first run.

## Get started

```sh
qqq login --server https://your-qqq-server       # device flow, browser (PKCE), Auth0, TABLE_BASED or a session
qqq home                                         # what you can open and do
qqq table query person -w "lastName STARTS_WITH S" -o -id -l 5
qqq process run greetInteractive -r 1,2 -v greetingPrefix=Hi
qqq ui                                           # the terminal UI on the same profile
qqq doctor                                       # connection, sign-in, terminal, and the build for support
```

## What is in it

**The terminal UI (`qqq ui`)**: a classic full-screen UI with a function-key bar, Home, the F9 command
center and F2 go-to, a server-paged grid (sort, filter builder or grammar, quick search, statistics, saved
views, variants, export), records with forms, contingent pickers, uploads and downloads, audits, tags and
sharing, the process wizard, the bulk-load wizard, reports and saved-report editors, dashboards and
widgets that act, developer mode, F1 help from the application, every sign-in type, themes, and a terminal
check that finds tmux key and colour problems and offers fixes.

**The CLI (`qqq <noun> <verb>`)**: tables (query, count, stats, get, create, copy, update, delete, export,
children, downloads and uploads, variants, columns), bulk insert, edit and delete from CSV or Excel,
processes with every step screen, async jobs and cancel, reports and saved reports (pivots, schedules),
saved views, sharing, audits, widgets and dashboards as text, home and find, preferences, help, every
extension the server installs (`qqq esb`, `qqq collab`, ...), developer mode, and `qqq api` for any of
the 202 UI API operations. JSON, table, text, CSV and YAML output with JMESPath `--query`; shell
completion for bash, zsh, fish and PowerShell; sign-ins in the OS keyring; profiles like `aws --profile`.

**Parity**: every row of the web UI's acceptance matrix that applies to a terminal passes in both the CLI
and the UI, or is blocked on a filed server issue.

## Known limitations

- Text filters ask the server for case-insensitive matching, but servers do not read that option over the
  UI API yet (qqq#1358), so matching stays case-sensitive until they do.
- Jobs need a server with durable jobs. Auth0 sign-in has not been tried against a real tenant.
- The Windows and Intel macOS binaries are cross-compiled; until the macOS and Windows CI lanes run, they
  are not tested before a release.
